# منظومة حجز مواعيد العيادات

واجهة عربية RTL متجاوبة، تتكون من:
- `index.html`: رابط الزبون.
- `admin.html`: رابط الإدارة.
- `schema.sql`: الجداول وسياسات الوصول في Supabase.
- `config.js`: بيانات الربط.
- `app.js`, `admin.js`, `style.css`: منطق الموقع والتصميم.

## تنبيه مهم
GitHub Pages يستضيف ملفات الواجهة الثابتة فقط؛ لا يستضيف قاعدة بيانات ولا PHP. هذا المشروع يستخدم Supabase كقاعدة بيانات وخدمة تسجيل دخول. لا تعتبر النسخة جاهزة للاستخدام الطبي الفعلي قبل مراجعة الأمان وسياسات البيانات.

## خطوات الإعداد

1. أنشئ مشروعاً في Supabase.
2. افتح **SQL Editor** والصق كامل محتوى `schema.sql` ثم اضغط Run.
3. من **Project Settings → API** انسخ Project URL و anon/publishable key.
4. افتح `config.js` واستبدل:
   - `PASTE_YOUR_SUPABASE_PROJECT_URL_HERE`
   - `PASTE_YOUR_SUPABASE_ANON_OR_PUBLISHABLE_KEY_HERE`
   لا تستخدم `service_role` key أبداً داخل ملفات الموقع.
5. في Supabase افتح **Authentication → Users → Add user** وأنشئ حساب الإدارة ببريد إلكتروني وكلمة مرور قوية.
6. انسخ UUID الخاص بالمستخدم من صفحة Users، ثم نفّذ في SQL Editor (استبدل UUID بالقيمة الفعلية):
   ```sql
   insert into public.staff_profiles(user_id, role, display_name)
   values ('PUT-AUTH-USER-UUID-HERE', 'admin', 'إدارة العيادة');
   ```
   لا تستخدم كلمة مرور `123` في موقع منشور. شاشة الدخول تستخدم حساب Supabase Auth، وليس بيانات ثابتة داخل HTML.
7. من **Table Editor** أضف الأقسام إلى `departments` أو أضفها لاحقاً من لوحة الإدارة.
8. ارفع كل الملفات إلى مستودع GitHub عام أو خاص، وفعّل **Settings → Pages → Deploy from branch**.
9. افتح رابط `index.html` المنشور للزبائن، ورابط `admin.html` للإدارة. لا ترفع ملف يحتوي أسراراً.
10. جرّب حجزاً وهمياً، تحديث الحالة من لوحة الإدارة، إلغاء الحجز وتنزيل الإيصال قبل الإعلان عن الموقع.

## ملاحظات التشغيل والأمان

- صفحة الإدارة تعتمد على Supabase Auth وصلاحية `admin` في جدول `staff_profiles`.
- لا توجد كلمات مرور أطباء محفوظة في جدول الأطباء. حقل اسم المستخدم/كلمة المرور في نموذج الطبيب ليس نظام دخول فعلياً حالياً؛ إدارة حسابات الأطباء تتطلب إضافة آلية Auth وربط كل حساب بدور `doctor`.
- إصدار الإيصال يتم عبر نافذة الطباعة في المتصفح؛ اختر **حفظ بصيغة PDF** في نافذة الطباعة. هذا يتجنب مكتبات PDF خارجية، ويعمل على أغلب المتصفحات.
- النسخة الحالية تستخدم سياسة قراءة عامة لبيانات قائمة الانتظار، وتعرض أرقام الحالات وحالتها. راجع ما إذا كان هذا مناسباً لخصوصية العيادة قبل النشر.
- ميزة «حجوزاتي» تعتمد على رقم الهاتف؛ لذلك ليست تحقق هوية قوياً. لا تستخدمها لعرض معلومات طبية حساسة. لحماية أفضل، أضف رمز OTP أو رابطاً سرياً لكل حجز، مع تحديد عدد المحاولات.
- الترقيم الحالي يتم من الواجهة، وقد ينتج رقم مكرر إذا حجز شخصان في نفس اللحظة. قبل الاستخدام الفعلي، انقل توليد رقم الحالة إلى دالة قاعدة بيانات ذرية (transaction/sequence) لكل طبيب.
- يجب ضبط قواعد إلغاء الحجز لتمنع إلغاء حجز شخص آخر، ويفضل استخدام رمز تحقق. لا تخزن تشخيصات أو معلومات طبية حساسة في الملاحظات.
- إعدادات شعار الصورة حالياً تقبل رابط صورة عام؛ رفع الملف نفسه يحتاج إعداد Supabase Storage أو خدمة تخزين أخرى.

## بنية الروابط
- الزبائن: `https://YOUR-USERNAME.github.io/YOUR-REPOSITORY/`
- الإدارة: `https://YOUR-USERNAME.github.io/YOUR-REPOSITORY/admin.html`

## بيانات تجريبية اختيارية
بعد تنفيذ المخطط، أضف أقساماً من لوحة الإدارة بعد تسجيل الدخول، أو نفّذ:
```sql
insert into public.departments(name) values
('قسم العيون'), ('قسم الأسنان'), ('قسم العظام')
on conflict(name) do nothing;
```

## تحديث شاشة الطبيب (الإصدار المعدّل)

أضيفت صفحة `doctor.html` للطبيب، وأصبحت لوحة الإدارة تنشئ حساب الطبيب بالبريد وكلمة المرور وتربطه بملف الطبيب. رابط الطبيب هو `doctor.html`، ورابط الإدارة يبقى `admin.html`، أما صفحة المراجع فهي `index.html` ولا تعرض رابط لوحة الإدارة.

### خطوات ضرورية بعد رفع الملفات
1. افتح Supabase ثم **SQL Editor** وشغّل ملف `schema.sql` كاملاً من جديد. يتضمن تحديثات آمنة نسبيًا لربط حساب الطبيب بملفه، وإظهار الحالات المكتملة للمراجع عند البحث بالاسم ورقم الهاتف.
2. انشر Edge Function الموجودة في `supabase/functions/create-doctor-account/index.ts` باسم `create-doctor-account`. من جهاز عليه Supabase CLI، من مجلد المشروع:
   ```bash
   supabase functions deploy create-doctor-account
   ```
3. تأكد أن أسرار الدالة في Supabase تشمل `SUPABASE_URL` و`SUPABASE_ANON_KEY` و`SUPABASE_SERVICE_ROLE_KEY`. عادةً يوفر Supabase هذه القيم تلقائيًا داخل Edge Functions؛ لا تضع `SERVICE_ROLE_KEY` في ملفات الموقع أو GitHub.
4. سجّل الدخول إلى `admin.html` بحساب مدير العيادة، ثم أضف الطبيب مع بريده الإلكتروني وكلمة مرور لا تقل عن 8 أحرف. إذا لم تكن الدالة منشورة، فلن يكتمل إنشاء الطبيب وحسابه.
5. أعط الطبيب رابط `doctor.html` وبيانات الدخول. يمكنه تغيير حالته إلى «موجود/غير موجود»، ومراجعة الحالات التابعة لعيادته، وتحويلها إلى «مكتملة»؛ الحالات المكتملة تظهر للمراجع عند إدخال الاسم ورقم الهاتف المطابقين.
6. في صفحة المراجع، تبويب «حجوزاتي» يتطلب الاسم الكامل ورقم الهاتف معًا. وفي لوحة الإدارة يمكن تسجيل حالة جديدة مع رقم هاتف المراجع.

**مهم:** اختبر النظام ببيانات وهمية أولًا. هذا المشروع نموذج أولي وليس بديلًا عن مراجعة أمنية مستقلة قبل استخدامه مع بيانات مرضى حقيقية. يُنصح أيضًا بتحويل توليد أرقام الحالات إلى دالة قاعدة بيانات ذرّية لمنع تكرار الرقم عند الحجز المتزامن، ومراجعة سياسات الوصول وتدقيقها قبل الإطلاق الفعلي.
